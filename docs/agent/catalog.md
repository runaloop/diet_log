# Добавление продукта без пропусков

1. Найти КБЖУ или взять числа пользователя без поиска. Числа — на порцию `--port`.
2. Выбрать группы и качество жира. Допустимые имена: `scripts/db choices`.
3. Сохранить всё **одним `scripts/db add`**, прочитать ответ. Разметку агент решает самостоятельно; неизвестный рецепт не повод спрашивать пользователя или откладывать запись.

```bash
scripts/db add "Орех пекан" --port 100г --k 690 --b 9.17 --zh 71.97 --u 13.86 --fiber 9.6 \
  --group орехи=1 --fat-quality good --alias "пекан"
```

Новый продукт требует `--port`, `--k`, `--b`, `--zh`, `--u`. Агент автоматически выбирает разметку по правилам ниже; если флаги пропущены, код сохраняет неизвестный состав, а не блокирует запись.
Клетчатка и реальная порция `--serving 20г` — если известны. Источник чисел — в ответе;
усреднение/подмена близким продуктом — также `--estimate`.

## Группы: агент выбирает без вопросов о рецепте

- `--group орехи=1` — известная группа. Для нескольких повторять `--group`.
- `--group … --groups-estimate "основание"` — приблизительная разметка по типичному составу. Сохраняются веса и основание, проверка завершена.
- `--no-groups "причина"` — уверенно не относится ни к одной группе (вода/кофе без добавок).
- `--groups-unknown "причина"` — даже полезная оценка невозможна. Группы не засчитываются, проверка завершена. Старое имя `--review-groups` означает то же самое.

КБЖУ и разметка независимы: `--estimate` относится **только к КБЖУ**. Числа пользователя/карточки не становятся оценкой из-за приблизительных групп. `--no-estimate` снимает ошибочную старую отметку оценки КБЖУ, не меняя чисел.

| Продукт | Группа |
|---|---|
| Овощи, зелень | `овощи` |
| Фрукты, ягоды | `фрукты` |
| Крупы, хлеб, макароны | `злаки` |
| Бобы, чечевица, горох | `бобовые` |
| Рыба, морепродукты | `рыба` |
| Орехи, семена | `орехи` |
| Молоко, йогурт, творог, сыр | `молочка` |
| Курица, индейка, утка | `птица` |
| Яйцо | `яйца` |
| Оливковое масло, оливки | `оливковое` |
| Говядина, свинина, баранина | `красное_мясо` |
| Десерты, сладости, снеки, переработанное мясо | `обработка` |
| Протеиновый порошок/коктейль, гейнер | `добавки` |

Чистый продукт: вес `1`. Для рыбы/птицы вес — доля мяса по массе блюда;
для остальных — вклад в порцию группы, а не доля массы. Диапазон `(0, 1]`;
для концентрированной рыбы/птицы допускается `>1` (сушёные чипсы).
**Оценивать разрешено, выдавать оценку за рецепт запрещено.** Сначала использовать уже имеющийся состав; иначе — тип блюда и общие правила ниже. Не искать рецепт в интернете, если пользователь уже дал КБЖУ. Не восстанавливать точные доли из БЖУ: задача неоднозначна. Не добавлять овощи/орехи/молочку к десерту только из-за упоминания ингредиента.

### Единые ориентиры для приблизительной разметки

Это рабочие допущения для учёта, не справочные рецепты. При наличии состава он важнее. Оценку записывать один раз в карточку и переиспользовать.

- Куриный суп: птица `0.05–0.1` массы; для жидкого супа с Б≈2г/100г — `0.05`. Овощи `0.25` порции, если типичный суп с овощной заправкой; крупу/лапшу без указания не добавлять.
- Каша с фруктами: злаки `1`, фрукты `0.25`. Гречка с птицей: злаки `1`, птица около `0.3` массы. Кимбап с тунцом: рыба около `0.15` массы, овощи `0.25`; белый рис не считать цельными злаками.
- Сырники: молочка `0.5`; муку и яйца как малые добавки отдельно не засчитывать. Молочный коктейль: молочка `0.5`, обработка `1`.
- Бургеры, пицца, чебуреки: обработка `1`; обычная мясная начинка — красное мясо `0.5` порции, двойная котлета — `1`. Булка/панировка не дают порцию цельных злаков; сыр/овощные добавки не дают полноценную порцию молочки/овощей.
- Жареный картофель, картофель по-деревенски, кокосовые снеки: обработка `1`; не зачитывать автоматически овощи или орехи. Грибы в картофеле — овощи `0.25`.
- Фучжу по-корейски: бобовые `0.5` как приблизительный вклад соевой основы. Просто «салат со спаржей» не доказывает, что это фучжу: допустимо оставить неизвестным.
- Для других блюд выбрать похожий тип и записать допущение. Неизвестный вид мяса не выдавать за установленный. Если полезная оценка невозможна, сохранить `--groups-unknown`, без вопроса пользователю.

## Качество жира

- `--fat-quality good` — жир в основном из рыбы, орехов, семян, оливок, авокадо;
- `--fat-quality bad` — фритюр, промышленная выпечка, трансжиры; фритюр перебивает рыбу;
- `--fat-quality neutral` — молочка, яйца, цельное мясо, прочее по STRATEGY.md §7;
- `--fat-quality … --fat-estimate "основание"` — категория выбрана по типичному способу приготовления, а не известному составу;
- `--fat-unknown "причина"` — нейтральный по умолчанию, завершённое решение без предупреждений.

При жире ≥30% ккал или ≥5г на реальную порцию пропущенная категория автоматически сохраняется как неизвестная; ниже порога — `neutral`. Не спрашивать, на каком масле готовили магазинное/ресторанное блюдо.

## Обновления и проверка

- `db add "Имя" --alias "слово"` сохраняет КБЖУ, группы и причины проверки. Требования полной карточки относятся к **новому** продукту.
- Явные `--group` при `add` **заменяют весь набор групп**. `--no-groups`/`--groups-unknown` очищают старые группы; неизвестность не оставляет их как достоверные.
- `db tag "Имя" группа=вес …` дополняет/обновляет группы; существующая отметка приблизительности сохраняется. Для замены всего набора и его основания использовать `db add --group …`. `db add … --fat-quality …` завершает проверку качества жира.
- `db review` — действительно неразмеченные старые карточки; `db review --all` — также принятые оценки и неизвестность с причинами. Старые `pending` с причинами автоматически переводятся в `unknown`, КБЖУ не меняются.
- Принятые оценки и неизвестность состава не сопровождаются повторными напоминаниями при записи еды, в отчёте за 7 дней и на новом дне. Не заменять их значками приблизительности, счётчиками или предложениями посмотреть допущения. Расчёты сохраняются: оценённые группы учитываются с записанными весами, неизвестные группы не засчитываются, неизвестный жир считается нейтральным.
- Если пользователь спрашивает, откуда взялось число, использовать сохранённые причины (`db review --all` или чтение через `db q`) и объяснить конкретное допущение. Не выдавать его за известный рецепт и не задавать повторных вопросов о составе. Исправлять данные по явному уточнению пользователя. Сообщения о нераспознанных записях, действительно незавершённых старых карточках и неполных дневниках сохраняются.
- Испытания только на временной базе: `DIET_DB=/tmp/каталог.db scripts/db init`, затем тот же `DIET_DB` перед каждым вызовом. Боевой каталог для тестов не использовать.

## Порядок поиска

```bash
scripts/db search-priority "Греческий йогурт Простоквашино" 10
scripts/db add "Греческий йогурт Простоквашино" --search-priority 10
```

`search_priority` — отдельный приоритет выдачи: целое число, по умолчанию `0`;
больше — выше, отрицательное — ниже. Сброс — `search-priority "Имя" 0`.
Команда требует точное каноническое имя. `add --search-priority` также доступен
при создании продукта; частичные обновления сохраняют прежнее значение.

Точное имя/алиас обрабатывается первым. Среди совпадений по подстроке выше
приоритет поиска, затем алфавит; при опечатках сначала степень совпадения и
полнота названия, затем приоритет и алфавит. Такой же порядок используется в
списках кандидатов при неоднозначности (`log.py`, `--pin`/`--exclude`, `db avail`).
Первый кандидат не выбирается автоматически: неоднозначность требует уточнения.
Для выбора без вопроса закрепить пользовательское сокращение алиасом.
Поле `priority` и команда `db priority` относятся только к составлению рациона.

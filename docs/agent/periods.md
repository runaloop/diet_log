# Итоги периода и недельная метрика

> Процедура для агента, читается по требованию. Ядро правил — `AGENTS.md`.

## Команды

```
python3 scripts/summary.py week [YYYY-MM-DD]        # ISO-неделя (пн–вс), содержащая дату; по умолчанию текущая
python3 scripts/summary.py month [YYYY-MM-DD]       # календарный месяц; по умолчанию текущий
python3 scripts/summary.py 2026-04-01..2026-04-30   # произвольный диапазон
python3 scripts/summary.py since-weight             # с последнего взвешивания + расчётный вес
```

Вывод показывать verbatim. «Итоги недели за 2026-03-09» / «итоги месяца за 2026-02» — передать дату. Вручную дневники не парсить; если нужны данные, которых скрипт не даёт, — только тогда.

## Что считает скрипт

- Дневники `diaries/YYYY/MM/DD.md` в диапазоне: нет файла — день пропущенный; файл есть, но записей нет — день без данных; есть хотя бы одна строка еды или тренировки — день с записью (только еда или только тренировка — частично заполненный, тоже считается). Пропущенные дни нулями не считаются.
- Из дневника берутся строка `**Потреблено:**` и строка `Базовый расход … Съедено … Потрачено … Дефицит` блока `## План`; при расхождении итогов с таблицей источник — таблица (`recalc_plan.py --write` чинит).
- Полнота: `полный` — записи за все дни; `частичный` — покрытие ≥80%; `недостаточно данных` — ниже 80%. При «недостаточно данных» вывода «цель выполнена / не выполнена» и интерпретации тренда по питанию нет.
- Дефицит сравнивается с целью по миксу окон дней с записями (STRATEGY.md §7a); белок — с флором; жиры/день — со средним диапазоном дня (без ×1.2-буфера).
- Вес: две и больше записи `config/user.md` внутри периода — изменение от первой к последней; одна — факт без изменения.
- День с маркером `> Неполный день` в средние не входит, перечисляется отдельно (см. `AGENTS.md` «Неполный день»).
- Текущий незавершённый день считается как обычный по имеющимся данным.

## Недельная накопительная метрика (`weektrend`)

`python3 scripts/summary.py weektrend [дата]` на старте дня и по команде «недельный прогресс» / «остаток недели»: H1 `# DD-MM-YYYY-Wnn (диапазон) | Режим: …` + тренд ISO-недели по записям **до** указанной даты (дефицит против микса окон дней, белок — только при недоборе, жиры — только вне диапазона 25–42% среднего бюджета, прогноз недели) + остаток групп и качество жира **скользящим окном 7 дней** (`ref−6..ref`); понедельник потолки и долги не обнуляет. `--no-groups` — только H1 + тренд (шапка нового дневника). В понедельник тренд сообщает «Первый день недели, тренда пока нет», остаток групп считается всё равно. Непривязанные к каталогу блюда перечисляются в конце — дыры каталога.

Образец:

```
# 15-06-2026-W25 (2026-06-15..2026-06-21) | Режим: похудение

- Средний суточный дефицит: 220 ккал (цель по миксу дней 150–320) ✓
- Белок: 145г/день (цель 143) ⚠ недобор 25г/день
- Прогноз недельного дефицита при тренде: 1540 ккал (окно 1050–2240) ✓

### Остаток групп (7 дней 2026-06-09..2026-06-15) — добрать
- рыба:         ⚠ 2.5/3 — добрать 0.5
- овощи:        ✗ 1.0/9 — добрать 8.0
…
### Остаток групп — потолки
- обработка:    ✗ 4.4/2 — перебор 2.4

### Качество жира (7 дней 2026-06-09..2026-06-15)
- bad: ⚠ 17% (потолок 15) — фритюр/выпечка/переработка
- good 28% — можно больше (ориентир 40+): рыба, орехи, оливковое
```
